---------------------------------------------------
- Теоретическая основа: теория протекания (перколяции) через систему случайно
  распределенных узлов (модель дискретной узловой перколяции, site percolation).
- Модель эксперимента:
  * Прямоугольное (или квадратное) поле, разбитое на одинаковые клетки.
  * Каждая клетка независимо от остальных открыта (проходима) с вероятностью p

    проходимых клеток, соединяющий верхнюю и нижнюю границы поля (начальная
    и конечная клетки в этих строках могут быть любыми).
- Требования к реализации:
  * Проведение серий экспериментов для различных значений вероятности p.
  * Оценка вероятности перколяции как доли успешных экспериментов для каждого p.
  * Построение графика зависимости вероятности перколяции P(p) от вероятности

3.1. Метод Монте-Карло для числа π
----------------------------------
Рассматривается единичный квадрат на плоскости:
    Ω = {(x, y) : 0 <= x <= 1, 0 <= y <= 1}.
Площадь квадрата:
    S_sq = 1 * 1 = 1.

Внутри квадрата рассматривается область A, ограниченная четвертью окружности
единичного радиуса с центром в начале координат (0, 0):
    A = {(x, y) ∈ Ω : x^2 + y^2 <= 1}.
Площадь этой области:
    S_circ = (1/4) * π * R^2 = π / 4  (так как R = 1).

Согласно геометрическому определению вероятности, если точка (X, Y) выбирается
равномерно в Ω, то вероятность ее попадания в область A равна:
    P(A) = S_circ / S_sq = (π / 4) / 1 = π / 4.

Следовательно:
    π = 4 * P(A).

По закону больших чисел (ЗБЧ) Чебышёва/Бернулли, при проведении n независимых
испытаний относительная частота успехов m / n сходится по вероятности к
истинной вероятности P(A):
    lim_{n -> ∞} (m / n) = P(A) = π / 4.

Оценка числа π на шаге n:
    π_est(n) = 4 * (inside_count / n).

Скорость сходимости:
Случайная величина I_k = I{(X_k, Y_k) ∈ A} является бернуллиевской величиной
с параметром p = π/4 ≈ 0.7854.
Дисперсия индикатора: Var(I_k) = p(1 - p) ≈ 0.7854 * 0.2146 ≈ 0.1685.
Дисперсия оценки π_est:
    Var(4 * (1/n) * sum(I_k)) = 16 * Var(I_k) / n ≈ 2.697 / n.
Стандартное отклонение (характерная погрешность):
    σ = sqrt(Var) ≈ 1.64 / sqrt(n).

По центральной предельной теореме (ЦПТ):
    |π_est(n) - π| ~ O(1 / sqrt(n)) = O(n^{-0.5}).

Именно поэтому автор решения выбрал двойной логарифмический масштаб (log-log):
    log(|ошибка|) ≈ log(C) - 0.5 * log(n).
На графике в log-log координатах облако ошибок ложится вдоль прямой с наклоном -0.5,
что идеально иллюстрирует фундаментальный закон сходимости метода Монте-Карло.

3.2. Теория перколяции (Часть 2)
--------------------------------
Рассматривается двумерная дискретная решетка размером Rows x Cols (в коде 40 x 40).
Узлы решетки (клетки) независимы друг от друга. Каждый узел открыт с вероятностью p.

Два узла считаются связанными, если они оба открыты и имеют общую сторону
(расстояние Манхэттена равно 1).
Событие перколяции E состоит в том, что существует хотя бы один связный кластер
открытых клеток, содержащий клетку из строки 0 (верх) и клетку из строки Rows-1 (низ).

Теоретический контекст:
В бесконечной квадратной решетке (L -> ∞) существует строго определенная
критическая точка фазового перехода второго рода (критический порог):
    p_c ≈ 0.592746...
При p < p_c вероятность образования бесконечного проводящего пути строго равна 0.
При p > p_c эта вероятность строго больше 0 и быстро стремится к 1.

Для конечной решетки (например, 40 x 40) резкая ступенька размывается в
гладкую S-образную сигмоидную кривую (эффект конечных размеров, finite-size scaling):
- При p <= 0.50 вероятность перколяции близка к нулю (в эксперименте автора: 0.00).
- В окрестности p_c ≈ 0.59 происходит резкий скачок (при p = 0.55 -> P = 0.06;
  при p = 0.60 -> P = 0.65; при p = 0.65 -> P = 0.94).
- При p >= 0.70 вероятность практически достигает 1.00.

Автор кода совершенно справедливо добавил вертикальную линию `p = 0.5927`,
подчеркивая соответствие численного эксперимента теоретическому фазовому переходу.

4.2. Часть 1: Оценка числа π (строки 9–32)

Строки 9–18:
```python
def estimate_pi(n):
    inside = 0
    est = []
    for i in range(1, n + 1):
        x, y = random.uniform(0, 1), random.uniform(0, 1)
        if x * x + y * y <= 1:
            inside += 1
        est.append(4 * inside / i)
    return est
```
Разбор функции:
- `inside = 0`: счетчик точек, попавших внутрь четверти круга.
- `est = []`: массив накопленных оценок числа π на каждом шаге от 1 до n.
- `for i in range(1, n + 1)`: цикл по общему количеству бросков. Индекс `i`
  одновременно является текущим количеством испытаний.
- `x, y = random.uniform(0, 1), random.uniform(0, 1)`: генерация двух независимых
  координат, равномерно распределенных на отрезке [0, 1]. Точка (x, y) равномерно
  заполняет единичный квадрат.
- `if x * x + y * y <= 1`: проверка уравнения четверти круга радиуса R=1.
  Если условие выполнено, увеличиваем счетчик `inside`.
- `est.append(4 * inside / i)`: текущая оценка числа π вычисляется как
  4 * (доля успехов на шаге i).
- Алгоритм инкрементальный: не тратит $O(n^2)$ времени на генерацию отдельных
  выборок под каждый размер $i$, а накапливает результат за один проход $O(n)$.

4.3. Часть 2: Моделирование перколяции (строки 34–73)
--------------------------------------------------------------------------------
Строки 35–36:
```python
def grid(rows, cols, p):
    return [[random.random() < p for _ in range(cols)] for _ in range(rows)]
```
- Генерирует двумерную матрицу размером `rows` x `cols` булевых значений
  (`True` — клетка проходима, `False` — заблокирована).
- `random.random() < p` возвращает `True` с вероятностью ровно p, так как
  `random.random()` равномерно распределен на полуинтервале [0.0, 1.0).
- Использовано чистое списковое включение (list comprehension).

Строки 38–54:
```python
def percolates(g, rows, cols):
    visited = [[False] * cols for _ in range(rows)]
    q = deque()
    for j in range(cols):
        if g[0][j]:
            q.append((0, j)); visited[0][j] = True
    while q:
        i, j = q.popleft()
        if i == rows - 1:
            return True
        for di, dj in ((-1, 0), (1, 0), (0, -1), (0, 1)):
            ni, nj = i + di, j + dj
            if 0 <= ni < rows and 0 <= nj < cols \
               and not visited[ni][nj] and g[ni][nj]:
                visited[ni][nj] = True
                q.append((ni, nj))
    return False
```
Разбор алгоритма поиска пути (BFS - Breadth-First Search):
- `visited = [[False] * cols for _ in range(rows)]`: двумерная матрица для
  отслеживания уже посещенных узлов, чтобы избежать зацикливания и повторных обходов.
- `q = deque()`: очередь вершин для обхода в ширину.
- Мульти-старт (строки 41–43):
  Проверяются все клетки верхней строки `i = 0`. Каждая проходимая клетка
  `g[0][j] == True` добавляется в очередь и помечается как `visited[0][j] = True`.
  Это моделирует протекание жидкости/тока сразу со всей верхней границы поля.
- Основной цикл `while q`:
  * `i, j = q.popleft()`: достаем очередную клетку из начала очереди за O(1).
  * `if i == rows - 1: return True`:
    РАННЯЯ ОСТАНОВКА (Early Exit). Как только мы достигли любой клетки нижней строки,
    факт перколяции доказан! Нет никакой необходимости продолжать обход оставшейся
    части графа. Это существенно ускоряет моделирование при p > p_c.
  * Цикл по 4 соседям: `((-1, 0), (1, 0), (0, -1), (0, 1))` — вверх, вниз, влево, вправо.
  * Условия перехода к соседней клетке (ni, nj):
    1. `0 <= ni < rows and 0 <= nj < cols` — клетка внутри границ сетки.
    2. `not visited[ni][nj]` — клетка еще не исследована.
    3. `g[ni][nj]` — клетка проходима.
  * Если все условия выполнены: отмечаем клетку `visited[ni][nj] = True` и
    добавляем ее координаты в очередь `q.append((ni, nj))`.
- Если очередь опустела, а нижняя строка так и не была достигнута, функция
  возвращает `False`.

6. ЗАМЕЧАНИЯ, СЛАБЫЕ МЕСТА И БАГ КОДИРОВКИ НА WINDOWS
================================================================================

1. Баг вывода в консоль Windows (UnicodeEncodeError):
   В строке 32:
       print(f"π ≈ {estimates[-1]:.6f}, ошибка = {errors[-1]:.6f}")
   В операционной системе Windows стандартная кодировка консоли часто установлена
   в CP1251 или CP866. Символы греческой буквы 'π' (U+03C0) и знака приближения '≈' (U+2248)
   отсутствуют в этих кодовых страницах. В результате запуск скрипта на чистой системе
   падает с исключением:
       UnicodeEncodeError: 'charmap' codec can't encode character '\u03c0'
   Исправление:
   Либо настроить в коде UTF-8:
       import sys
       sys.stdout.reconfigure(encoding='utf-8')
   Либо написать строку с использованием стандартных ASCII-символов:
       print(f"pi ~= {estimates[-1]:.6f}, error = {errors[-1]:.6f}")

2. Потребление памяти и отрисовка графика Монте-Карло:
   Список `estimates` и список `errors` хранят по 100 000 чисел `float`.
   Хотя 100 000 чисел занимают немного оперативной памяти (~1–2 МБ), вызов
   `plt.plot(range(1, N + 1), errors)` пытается отрисовать векторную полилинию
   из 100 000 отрезков. Из-за этого генерация картинки `pi_error.png` занимает
   несколько секунд, а в самом файле точки в конце сливаются в сплошную полосу.
   Более элегантное решение — прореживать точки для графика (например, брать
   точки с логарифмическим шагом или каждый 10-й / 100-й шаг при больших n).

3. Отсутствие прогресс-бара или логов в Части 2:
   Вычисление 21 * 100 = 2100 экспериментов перколяции на поле 40x40 занимает
   около 4–6 секунд. Программа в это время "молчит". Добавление простого индикатора
   или вывода помогло бы пользователю понимать, что процесс идет.

4. Геометрическая формулировка:
   В тексте методички говорится: "точка попадет в круг, вписанный в этот квадрат".
   В коде используется условие `x*x + y*y <= 1` для `x, y ∈ [0, 1]`, что соответствует
   четверти круга единичного радиуса.
   С точки зрения теории вероятностей и отношения площадей:
   - Вписанный круг в квадрат [0, 1]^2: центр (0.5, 0.5), радиус r = 0.5.
     Площадь круга = π * r^2 = π * 0.25 = π / 4. Площадь квадрата = 1.
     Отношение площадей = π / 4.
   - Четверть круга радиуса 1 в квадрате [0, 1]^2:
     Площадь сектора = (1/4) * π * 1^2 = π / 4. Площадь квадрата = 1.
     Отношение площадей = π / 4.
   Результат математически абсолютно идентичен, однако четверть круга формульно
   проще (не нужно вычитать 0.5 из координат x и y).

Ниже приведена улучшенная версия скрипта с исправлением ошибки кодировки Windows,
оптимизированным сохранением точек для графика и понятными комментариями:

```python
import random
import math
import sys
import matplotlib.pyplot as plt
from collections import deque

# 0. Обеспечиваем корректный вывод UTF-8 в консоль Windows
if sys.platform == "win32":
    try:
        sys.stdout.reconfigure(encoding='utf-8')
    except AttributeError:
        pass

# 1. Фиксация начального состояния генератора (по заданию)
SEED = 42
random.seed(SEED)

# ==========================================
# ЧАСТЬ 1: Оценка числа π (Монте-Карло)
# ==========================================
def estimate_pi(n, subsample=True):
    inside = 0
    ns = []
    errors = []
    
    for i in range(1, n + 1):
        x = random.uniform(0, 1)
        y = random.uniform(0, 1)
        if x * x + y * y <= 1.0:
            inside += 1
        
        # Для графика сохраняем либо первые 1000 точек, либо прореженные дальше,
        # чтобы не перегружать память и matplotlib 100 000 точками
        if not subsample or i <= 1000 or i % 50 == 0 or i == n:
            pi_est = 4.0 * inside / i
            ns.append(i)
            errors.append(abs(pi_est - math.pi))
            
    final_pi = 4.0 * inside / n
    return ns, errors, final_pi

N = 100_000
plot_n, plot_errors, pi_final = estimate_pi(N)
final_error = abs(pi_final - math.pi)

plt.figure(figsize=(8, 4))
plt.plot(plot_n, plot_errors, linewidth=0.8, color='tab:blue')
plt.xscale('log')
plt.yscale('log')
plt.xlabel("Число испытаний n (log)")
plt.ylabel("Абсолютная ошибка |π_est - π| (log)")
plt.title("Ошибка оценки π методом Монте-Карло")
plt.grid(True, which="both", alpha=0.3)
plt.tight_layout()
plt.savefig("pi_error.png", dpi=150)
plt.close()

print(f"Часть 1: π ≈ {pi_final:.6f}, ошибка = {final_error:.6f}")

# ==========================================
# ЧАСТЬ 2: Моделирование перколяции
# ==========================================
def grid(rows, cols, p):
    """Генерация решетки: True - проходимая клетка, False - заблокированная."""
    return [[random.random() < p for _ in range(cols)] for _ in range(rows)]

def percolates(g, rows, cols):
    """Проверка существования пути сверху вниз алгоритмом BFS."""
    visited = [[False] * cols for _ in range(rows)]
    q = deque()
    
    # Старт со всех открытых клеток верхней строки
    for j in range(cols):
        if g[0][j]:
            q.append((0, j))
            visited[0][j] = True
            
    while q:
        i, j = q.popleft()
        # Если достигли нижней строки - перколяция есть (ранний выход)
        if i == rows - 1:
            return True
        for di, dj in ((-1, 0), (1, 0), (0, -1), (0, 1)):
            ni, nj = i + di, j + dj
            if 0 <= ni < rows and 0 <= nj < cols:
                if not visited[ni][nj] and g[ni][nj]:
                    visited[ni][nj] = True
                    q.append((ni, nj))
    return False

ROWS = COLS = 40
TRIALS = 100
ps = [i / 20.0 for i in range(21)]
probs = []

print("\nЧасть 2: Моделирование перколяции...")
for p in ps:
    wins = sum(percolates(grid(ROWS, COLS, p), ROWS, COLS) for _ in range(TRIALS))
    probs.append(wins / TRIALS)

plt.figure(figsize=(8, 4))
plt.plot(ps, probs, marker='o', color='tab:blue', label="Эксперимент (40x40)")
plt.axvline(0.5927, color='red', linestyle='--', linewidth=1.2, label="Теоретический порог p_c ≈ 0.5927")
plt.xlabel("Вероятность проходимости клетки p")
plt.ylabel("Вероятность перколяции P(p)")
plt.title(f"Перколяция, поле {ROWS}x{COLS}, {TRIALS} экспериментов на точку")
plt.legend()
plt.grid(True, alpha=0.3)
plt.tight_layout()
plt.savefig("percolation.png", dpi=150)
plt.close()

print("\nРезультаты перколяции:")
for p, v in zip(ps, probs):
    print(f"p = {p:.2f}  |  P = {v:.2f}")
```
