1. АРХИТЕКТУРА ГЕНЕРАЦИИ СЛУЧАЙНЫХ ЧИСЕЛ В C++ (<random>)
--------------------------------------------------------------------------------
В классическом Си генерация выполнялась через rand() и srand(time(NULL)).
В современном C++ (начиная с C++11) этот подход признан устаревшим и ошибочным:
- rand() выдает числа в диапазоне всего до RAND_MAX (часто лишь 32767).
- Плохое статистическое качество (младшие биты повторяются, короткий период).
- Глобальное скрытое состояние, приводящее к гонкам данных в многопоточности.

В C++11 библиотека <random> разделена на 3 независимых компонента («трехслойный пирог»):
  1) Источник энтропии (Seed)         --> std::random_device
  2) Алгоритмический генератор (PRNG) --> std::mt19937
  3) Распределение (Distribution)     --> std::uniform_int_distribution


--------------------------------------------------------------------------------
2. std::random_device: ИСТОЧНИК ЭНТРОПИИ (ЗЕРНО / SEED)
--------------------------------------------------------------------------------
std::random_device предназначен для получения первичного неделимого случайного
числа (зерна) напрямую из аппаратных и системных источников.

Как это работает:
- Обращается к операционной системе (в Windows — CryptGenRandom / BCrypt,
  в Linux — /dev/urandom) и аппаратным инструкциям процессора (RDRAND).
- Черпает энтропию из физического «шума» компьютера (микротайминги прерываний,
  задержки диска, сетевые пакеты, датчики температур).

Почему НЕЛЬЗЯ использовать ТОЛЬКО random_device для всех случайных чисел:
1. Низкая производительность: каждый вызов random_device — это дорогой системный
   вызов ядра ОС или аппаратная задержка. Он в сотни раз медленнее математических
   алгоритмов в памяти.
2. Истощение энтропии: системный пул энтропии ОС ограничен; вычерпывать его ради
   простых бросков кубика или расчетов нерационально.
3. Невозможность отладки: невозможно зафиксировать последовательность, чтобы
   воспроизвести плавающий баг в симуляции.
4. Допуск стандарта: стандарт C++ допускает, что на платформах без аппаратного
   источника random_device может работать детерминированно (так было в старых MinGW).

Вывод: random_device используется ТОЛЬКО ОДИН РАЗ — чтобы передать качественный
seed в псевдослучайный генератор.


--------------------------------------------------------------------------------
3. std::mt19937: АЛГОРИТМИЧЕСКИЙ ПСЕВДОСЛУЧАЙНЫЙ ГЕНЕРАТОР (PRNG)
--------------------------------------------------------------------------------
std::mt19937 — это реализация алгоритма «Вихрь Мерсенна» (Mersenne Twister),
разработанного в 1997 году Макото Мацумото и Такудзи Нисимурой.

Особенности и преимущества:
1. Гигантский период: 2^19937 - 1. Это число состоит из более чем 6000 знаков.
   Последовательность чисел никогда не закольцуется и не начнет повторяться
   за время работы любых вычислений.
2. Высочайшая скорость: генерация состоит из битовых сдвигов и операций XOR
   в регистрах процессора.
3. Отличное многомерное распределение: псевдослучайные точки не группируются
   в плоскости и гиперплоскости (отсутствие дефектов линейных конгруэнтных генераторов).
4. Внутреннее состояние: генератор хранит массив из 624 32-битных целых чисел
   (~2.5 КБ памяти) и указатель текущей позиции.


--------------------------------------------------------------------------------
4. РАСПРЕДЕЛЕНИЯ: std::uniform_int_distribution И ПРОБЛЕМА MODULO BIAS
--------------------------------------------------------------------------------
Сырой генератор mt19937 выдает числа во всем диапазоне uint32 (от 0 до 4 294 967 295).
Для получения диапазона (например, от 1 до 10) часто ошибочно используют оператор
взятия остатка: gen() % 10 + 1.

Почему оператор % ломает вероятность (Modulo Bias / Смещение остатка):
Представим генератор, выдающий числа от 0 до 6 (всего 7 равновероятных исходов).
Нам нужно получить число от 0 до 4 (5 исходов).
Берем остаток от деления на 5:
  0 % 5 = 0
  1 % 5 = 1
  2 % 5 = 2
  3 % 5 = 3
  4 % 5 = 4
  5 % 5 = 0  <-- снова 0!
  6 % 5 = 1  <-- снова 1!
В итоге:
  Вероятность получить 0 или 1: 2/7 ≈ 28.6%
  Вероятность получить 2, 3 или 4: 1/7 ≈ 14.3%
Вероятность выпадения первых чисел оказалась В ДВА РАЗА ВЫШЕ!

Как работает std::uniform_int_distribution:
- Распределение отсекает «лишний хвост» диапазона генератора (метод отбора
  с отклонением — rejection sampling).
- Гарантирует строго равную математическую вероятность для каждого элемента
  заданного отрезка [min, max].

5. РОЛЬ КЛЮЧЕВОГО СЛОВА static ВНУТРИ ФУНКЦИИ
--------------------------------------------------------------------------------
В функции hypotenuse_mod генератор и распределения объявлены как static:
    static std::mt19937 gen(std::random_device{}());
    static std::uniform_int_distribution<int> coin(0, 1);
    static std::uniform_int_distribution<int> bonus(1, 10);

Почему это критически важно:
1. Сохранение состояния между вызовами:
   Без static генератор пересоздавался бы при каждом вызове функции. Это привело
   бы к постоянному перезапуску генератора и сбросу его внутреннего цикла.
2. Производительность:
   Инициализация mt19937 требует заполнения таблицы из 624 чисел и системного
   вызова random_device. Благодаря static эта работа делается РОВНО ОДИН РАЗ
   за все время работы программы.
3. Инкапсуляция:
   Генератор спрятан внутри функции hypotenuse_mod. Он недоступен снаружи, не
   засоряет глобальную область видимости и не конфликтует с другими файлами проекта.
4. Ленивая инициализация (Lazy evaluation):
   Инициализация static-переменной внутри функции происходит только в момент
   первого вызова этой функции (по стандарту C++11 инициализация потокобезопасна).

6. БИБЛИОТЕКА <cmath> И ФУНКЦИЯ std::hypot
--------------------------------------------------------------------------------
Библиотека <cmath> — стандартная библиотека математических функций C++ (аналог
Си-библиотеки <math.h>, но функции размещены в пространстве имен std).

Функция std::hypot(a, b) вычисляет длину гипотенузы: c = sqrt(a^2 + b^2).

Почему std::hypot надежнее, чем std::sqrt(a * a + b * b):
1. Защита от переполнения (overflow):
   Если катеты велики (например, a = 1e160), то операция a * a даст переполнение
   типа double (inf). std::hypot нормализует аргументы (делит на максимум перед
   возведением в квадрат) и вычисляет точный результат без промежуточного переполнения.
2. Защита от потери точности (underflow):
   Если числа экстремально малы, их квадраты могут обратиться в 0 (underflow).
   std::hypot сохраняет точность даже около границ машинного нуля.
